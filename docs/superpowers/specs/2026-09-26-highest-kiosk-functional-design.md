# HIGHEST 굿즈 키오스크 기능·화면 설계 명세

- 문서 상태: 사용자 검토 승인 기준안
- 작성일: 2026-09-26
- 적용 범위: 고객용 키오스크 화면과 로컬 관리자 화면
- 디자인 원칙 문서: [`HIGHEST_HORIZON_CONCEPT.md`](../../../HIGHEST_HORIZON_CONCEPT.md)

## 1. 목적

HIGHEST 팝업 스토어에서 사용하는 세로형 굿즈 판매 키오스크의 화면 구성, 사용자 흐름, 데이터 구조, 관리자 편집 범위와 결제 시뮬레이션 방식을 정의한다. 개발 시 상품·가격·이미지를 화면 코드에 직접 고정하지 않고 관리자 화면에서 즉시 교체할 수 있도록 데이터 중심 구조로 구현하는 것이 핵심이다.

본 프로젝트의 결제는 실제 금융 결제가 아닌 시뮬레이션이다. 계좌번호나 QR을 보여 주는 모드에서도 입금 여부를 자동 검증하지 않으므로 사용자에게 실제 결제가 확인되었다고 오인시키는 표현을 사용하지 않는다.

## 2. 확정된 핵심 결정

1. 고객 흐름은 `웰컴 → 상품 목록 → 상품 상세 → 주문 확인·결제 → 완료 → 웰컴` 순서다.
2. 모든 상품 대표·상세 이미지는 1:1 비율을 기본 규격으로 사용한다.
3. 상품 목록 상단, 로고 바로 아래에 카테고리 선택 영역을 둔다.
4. 상품 목록은 세로 스크롤되지만 별도의 스크롤바는 표시하지 않는다.
5. 목록 화면 하단의 `내가 담은 굿즈`와 결제 화면의 `주문 상품`은 내부 스크롤이 가능하며 현재 위치를 알 수 있는 스크롤 표시를 둔다.
6. 상품 목록 오른쪽 위에는 별도 장바구니 버튼을 두지 않는다.
7. 상품 목록 왼쪽 위에 `처음으로` 버튼을 둔다.
8. 상품 정보와 메인 배경은 비밀번호로 보호된 관리자 화면에서 수정한다.
9. 결제 방식은 관리자 화면에서 `즉시 완료`, `계좌·QR 안내`, `결제 시뮬레이션` 중 선택한다.

## 3. 디자인 기준과 참조 화면

공통 무드는 하늘, 구름, 별, 날개, 나침반을 활용한 청춘 아카데미 콘셉트다. 기본 색은 화이트와 스카이 블루, 강조색은 로열 블루와 별빛 옐로이며, 둥근 카드와 큰 터치 영역을 사용한다.

시각 참조 이미지는 다음과 같다. 참조 이미지는 분위기와 정보 위계의 기준이며, 이미지 안의 샘플 상품명·가격·인물·문구는 실제 운영 데이터가 아니다.

## 4. 전체 화면 흐름

```text
[웰컴]
   │ 굿즈 사러가기
   ▼
[상품 목록] ── 상품 선택 ──▶ [상품 상세]
   ▲                            │ 장바구니 담기 / 목록으로
   └────────────────────────────┘
   │ 구매하러 가기
   ▼
[주문 확인·결제]
   │ 결제하기 / 입금했어요 / 시뮬레이션 시작
   ▼
[결제 처리]
   │ 성공
   ▼
[결제 완료 또는 주문 접수]
   │ 처음으로 / 자동 초기화
   ▼
[웰컴]
```

뒤로 이동해도 현재 세션의 장바구니, 선택한 카테고리와 가능한 경우 상품 목록의 스크롤 위치를 유지한다. 주문 완료, 사용자의 명시적 초기화 또는 유휴 시간 만료 시 세션을 비운다.

## 5. 고객용 화면 명세

### 5.1 웰컴 화면

#### 표시 요소

- 화면에 딱 맞게 채워지는 세로형 메인 배경 이미지
- 콘셉트에 맞는 `굿즈 사러가기` 기본 행동 버튼
- 관리자가 설정한 경우 로고와 짧은 안내 문구

#### 동작

- `굿즈 사러가기`를 누르면 상품 목록으로 이동한다.
- 동일 세션에 미완료 장바구니가 있으면 이를 유지한 채 상품 목록으로 이동한다.
- 배경 이미지는 화면 비율에 맞춰 중앙 기준으로 채우되, 관리자 미리보기에서 잘리는 영역을 확인할 수 있어야 한다.

#### 관리자 편집 항목

- 배경 이미지 업로드·교체·삭제·기본값 복원
- 이미지 위치와 확대 배율 조정
- 선택적 로고·안내 문구 표시 여부와 내용

### 5.2 상품 목록 화면

#### 고정 영역

- 왼쪽 위 `처음으로` 버튼
- 중앙 로고
- 로고 바로 아래 카테고리 탭
- 화면 하단 `내가 담은 굿즈`, 총수량, 총액, `구매하러 가기` 버튼

#### 상품 영역

- 두 열 카드 그리드를 기본으로 사용한다.
- 각 카드에는 1:1 대표 이미지, 상품명, 가격, `+` 담기 버튼을 표시한다.
- 카드를 누르면 해당 상품 상세 화면으로 이동한다.
- `+` 버튼을 누르면 상세 화면을 거치지 않고 수량 1개를 장바구니에 추가한다.
- 상품 영역은 세로 스크롤되며 스크롤바는 숨긴다.
- 카테고리 탭은 `전체`를 첫 항목으로 제공하고, 나머지는 관리자 표시 순서를 따른다. 탭이 넘칠 경우 가로 스크롤하되 스크롤바는 숨긴다.
- 품절 상품은 흐리게 표시하고 `품절` 배지를 노출하며 담기 동작을 막는다.

#### 하단 장바구니

- 각 행에 썸네일, 상품명, 단가, 수량 감소, 현재 수량, 수량 증가, 행 합계를 표시한다.
- 여러 상품이 들어오면 장바구니 목록 부분만 세로 스크롤한다.
- 장바구니 목록에는 얇고 명확한 스크롤 표시를 둔다.
- 총수량, 총액과 `구매하러 가기` 버튼은 목록을 스크롤해도 고정한다.
- 장바구니가 비어 있으면 빈 상태 안내를 표시하고 구매 버튼을 비활성화한다.
- 수량 1에서 감소 버튼을 누르면 삭제 확인을 거친 뒤 행을 제거한다.

#### `처음으로` 동작

- 장바구니가 비어 있으면 즉시 웰컴 화면으로 이동한다.
- 장바구니에 상품이 있으면 `담은 상품을 비우고 처음 화면으로 돌아갈까요?` 확인창을 표시한다.
- 확인 시 장바구니와 세션 선택 상태를 초기화하고 웰컴 화면으로 이동한다.
- 취소 시 상품 목록에 그대로 머문다.

### 5.3 상품 상세 화면

#### 표시 요소

- 목록으로 돌아가는 뒤로가기 버튼
- 상품명, 가격, 카테고리, 판매 상태
- 1:1 대표 이미지와 1:1 상세 이미지 갤러리
- 상품 설명과 규격·구성·재질 등 관리자가 입력한 상세 정보
- 수량 조절기, 선택 수량 합계
- `장바구니 담기`와 `바로 구매` 버튼

#### 동작

- 이미지가 여러 장이면 가로 스와이프 또는 썸네일 선택으로 확인한다. 별도 스크롤바는 표시하지 않는다.
- `장바구니 담기`는 선택 수량을 추가하고 성공 안내 후 현재 화면에 머문다.
- `바로 구매`는 선택 수량을 추가한 뒤 주문 확인·결제 화면으로 이동한다.
- 뒤로가기는 선택한 카테고리와 목록 스크롤 위치를 복원한다.
- 품절이거나 비활성화된 상품은 담기와 바로 구매를 막고 상태를 안내한다.

### 5.4 주문 확인·결제 화면

#### 표시 요소

- 장바구니로 돌아가는 버튼
- 주문 상품 목록
- 상품 금액, 할인 금액, 최종 결제 예정 금액
- 결제 방식 또는 시뮬레이션 안내
- `주문 수정하기`와 최종 행동 버튼

#### 주문 상품 영역

- 각 행에 1:1 썸네일, 상품명, 수량, 행 합계를 표시한다.
- 상품이 많으면 목록 영역만 세로 스크롤한다.
- 오른쪽에 현재 위치를 나타내는 세로 스크롤 표시를 둔다.
- 합계와 결제 수단, 최종 행동 버튼은 목록 밖에 고정해 항상 보이게 한다.

#### 결제 모드별 동작

| 모드 | 화면 행동 버튼 | 처리 방식 | 최종 화면 제목 |
|---|---|---|---|
| 즉시 완료 | `결제하기` | 짧은 처리 애니메이션 후 완료 | `결제가 완료되었습니다` |
| 계좌·QR 안내 | `입금했어요` | 계좌·예금주·QR을 표시하고 사용자 확인 후 접수 | `주문이 접수되었습니다` |
| 결제 시뮬레이션 | `결제 시뮬레이션` | 카드 또는 간편결제 연출 후 완료 | `결제 시뮬레이션이 완료되었습니다` |

계좌·QR 안내 모드는 입금을 자동 확인하지 않는다. 따라서 `결제 완료`라는 표현 대신 `주문 접수`를 사용하고 운영자가 별도 확인해야 한다는 안내를 표시한다.

#### 결제 직전 검증

- 상품 활성·품절 상태와 현재 가격을 다시 읽는다.
- 담은 수량이 상품별 최대 수량을 넘으면 수정 안내를 표시한다.
- 가격이 바뀌었으면 새로운 금액과 변경 상품을 알려 주고 사용자가 다시 확인하게 한다.
- 중복 탭 방지를 위해 처리 시작 후 최종 행동 버튼을 잠근다.

### 5.5 결제 처리 화면

- 진행 중임을 알리는 별빛 또는 구름 애니메이션과 상태 문구를 표시한다.
- 처리 중에는 다른 결제 동작을 막는다.
- 시뮬레이션 실패 설정이 활성화된 경우 실패 안내와 `다시 시도`, `장바구니로`를 제공한다.
- 성공하면 주문 번호를 한 번만 생성하고 완료 화면으로 이동한다.

### 5.6 완료·접수 화면

#### 표시 요소

- 결제 모드에 맞는 완료 또는 접수 제목
- 주문 번호, 총액, 선택한 방식
- 굿즈 수령 안내
- `처음으로` 버튼과 자동 초기화 남은 시간

#### 동작

- `처음으로`를 누르면 장바구니와 주문 세션을 비우고 웰컴 화면으로 이동한다.
- 아무 동작이 없으면 20초 후 자동으로 초기화하여 웰컴 화면으로 이동한다.
- 자동 초기화 전 마지막 5초는 남은 시간을 명확히 표시한다.
- 주문 번호는 한 주문에 하나만 발급하며 동일 버튼을 반복 눌러도 중복 주문을 만들지 않는다.

## 6. 장바구니와 세션 규칙

- 장바구니는 상품 목록, 상세, 주문 확인 화면 사이에서 유지한다.
- 같은 상품을 다시 담으면 새 행을 만들지 않고 수량을 합친다.
- 상품별 수량은 1 이상, 관리자가 정한 최대 구매 수량 이하로 제한한다.
- 비활성화 또는 품절 전환된 상품은 새로 담을 수 없다.
- 이미 담은 상품이 결제 전에 품절·비활성화되면 해당 행을 강조하고 제거 또는 수량 수정을 요청한다.
- 가격은 장바구니에 담은 시점과 결제 직전에 비교하고, 변경 시 사용자의 재확인을 받는다.
- 고객 화면에서 90초간 입력이 없으면 15초 카운트다운 확인창을 표시한다. 계속 사용하지 않으면 세션과 장바구니를 초기화하고 웰컴 화면으로 돌아간다.
- 결제 처리 중에는 유휴 초기화를 일시 중지한다.

## 7. 관리자 화면

### 7.1 진입과 인증

- 일반 고객에게 노출되지 않는 로고 길게 누르기 또는 운영용 단축 동작으로 로그인 화면을 연다.
- 비밀번호가 맞아야 관리자 기능에 진입할 수 있다.
- 관리자 화면에서 5분간 입력이 없으면 자동 로그아웃한다.
- 비밀번호는 화면 코드에 평문으로 넣지 않고 해시된 값으로 저장한다.
- 로컬 단일 키오스크 운영을 전제로 한다. 네트워크에 공개할 경우 서버 인증, 접근 제어와 통신 암호화를 별도로 적용해야 한다.

### 7.2 상품 관리

관리자는 상품을 추가, 수정, 복제, 숨김 처리하고 표시 순서를 변경할 수 있다. 상품 데이터는 화면 레이아웃 코드와 분리한다.

| 필드 | 설명 | 규칙 |
|---|---|---|
| 상품 ID | 내부 식별자 | 생성 후 변경하지 않음 |
| 상품명 | 고객 화면 표시명 | 필수 |
| 가격 | 원화 판매가 | 0 이상의 정수 |
| 카테고리 | 분류 | 활성 카테고리 중 선택 |
| 대표 이미지 | 목록과 주문 썸네일 | 1:1 필수 |
| 상세 이미지 | 상세 갤러리 | 1:1, 여러 장 가능 |
| 설명 | 상품 소개 | 선택 |
| 상세 정보 | 구성·규격·재질 등 | 선택 가능한 키·값 목록 |
| 판매 상태 | 판매 중·품절 | 필수 |
| 공개 상태 | 노출·숨김 | 필수 |
| 표시 순서 | 목록 정렬 | 숫자가 작은 항목 우선 |
| 최대 수량 | 주문당 최대 구매 수량 | 1 이상의 정수 |

- 1:1이 아닌 이미지는 저장 전에 정사각형 자르기 화면을 제공한다.
- 업로드 직후 목록 카드, 상세 화면과 주문 썸네일 미리보기를 제공한다.
- 상품 삭제는 과거 주문 참조 문제를 막기 위해 기본적으로 영구 삭제가 아닌 숨김 처리한다.

### 7.3 카테고리 관리

- 카테고리 추가, 이름 수정, 노출 여부, 표시 순서를 편집한다.
- `전체`는 시스템이 자동 제공하며 삭제할 수 없다.
- 숨긴 카테고리는 고객 화면에 표시하지 않지만 상품 데이터와의 연결은 유지한다.

### 7.4 웰컴 화면 관리

- 메인 배경 이미지 업로드, 교체, 삭제와 기본 이미지 복원을 제공한다.
- 실제 키오스크 비율의 미리보기에서 이미지 확대와 기준 위치를 조정한다.
- 필요한 경우 로고와 안내 문구의 표시 여부를 편집한다.

### 7.5 결제 시뮬레이션 관리

- 결제 모드 세 가지 중 하나를 선택한다.
- 계좌·QR 모드에서는 은행명, 계좌번호, 예금주, QR 이미지와 안내 문구를 편집한다.
- 즉시 완료와 시뮬레이션 모드에서는 처리 연출 시간을 1~5초 범위에서 설정한다.
- 테스트를 위해 성공 또는 실패 결과를 선택할 수 있으나 운영 기본값은 성공이다.
- 완료 화면의 수령 안내 문구를 편집한다.

### 7.6 시스템 관리

- 관리자 비밀번호 변경과 로그아웃
- 상품·카테고리·화면·결제 설정을 하나의 백업 파일로 내보내기
- 백업 파일 가져오기 전 내용 검증과 최종 확인
- 초기 기본 데이터로 복원하기 전 관리자 비밀번호 재확인

## 9. 스크롤 표시 규칙

| 영역 | 스크롤 방향 | 스크롤 표시 |
|---|---|---|
| 상품 목록 | 세로 | 숨김 |
| 카테고리 탭 | 가로 | 숨김 |
| 상품 상세 이미지 | 가로 | 숨김, 페이지 위치 점 또는 썸네일 사용 가능 |
| 내가 담은 굿즈 | 세로 | 표시 |
| 주문 확인의 주문 상품 | 세로 | 표시 |

스크롤바를 숨기는 영역도 터치 드래그와 마우스 휠 입력을 모두 지원한다.

## 10. 빈 상태와 오류 상태

- 상품 없음: `등록된 상품이 없습니다`와 웰컴으로 돌아가기 제공
- 카테고리 결과 없음: `이 카테고리에 상품이 없습니다` 표시
- 장바구니 비어 있음: 구매 버튼 비활성화
- 이미지 불러오기 실패: 브랜드 색상의 기본 상품 이미지로 대체
- 잘못된 상품 데이터: 해당 상품 숨김 처리 후 관리자 로그에 원인 기록
- 가격·판매 상태 변경: 변경 내용을 명시하고 주문 재확인
- 결제 시뮬레이션 실패: 다시 시도 또는 장바구니 복귀
- 백업 가져오기 실패: 기존 데이터를 변경하지 않고 오류 원인 표시

## 11. 키오스크 사용성 기준

- 주요 터치 영역은 최소 48×48px 이상으로 구성한다.
- 주요 버튼과 가격은 배경 대비가 충분한 진한 블루를 사용한다.
- 호버 없이도 선택 여부와 버튼 상태를 이해할 수 있어야 한다.
- 금액은 `24,000원`처럼 천 단위 구분 기호를 사용한다.
- 빠른 연속 터치로 같은 상품이나 주문이 중복 처리되지 않게 입력을 잠시 제한한다.
- 상단과 하단의 장식은 핵심 버튼과 겹치지 않으며 기기 안전 영역을 반영한다.
- 오류 안내는 색상만이 아니라 아이콘과 문구를 함께 사용한다.

## 12. 화면별 승인 조건

### 웰컴

- 관리자에서 교체한 배경이 재빌드 없이 반영된다.
- 화면 비율이 달라도 빈 여백 없이 채워지고 핵심 피사체 위치를 조정할 수 있다.
- 시작 버튼이 상품 목록으로 이동한다.

### 상품 목록

- 모든 대표 이미지가 정사각형 프레임에 일관되게 표시된다.
- 로고 아래 카테고리로 목록이 즉시 필터링된다.
- 상품 영역은 스크롤되지만 스크롤바가 보이지 않는다.
- 하단 장바구니는 독립적으로 스크롤되며 스크롤 표시가 보인다.
- `처음으로`는 장바구니 상태에 따라 바로 이동 또는 초기화 확인을 수행한다.

### 상품 상세

- 여러 1:1 이미지를 확인할 수 있다.
- 수량과 합계가 연동되고 최대 수량을 넘지 않는다.
- 장바구니 담기와 바로 구매가 각각 정의된 화면으로 이어진다.
- 뒤로가면 목록 맥락이 보존된다.

### 주문 확인·결제

- 주문 상품이 많아도 상품 영역만 스크롤되고 합계와 결제 버튼은 고정된다.
- 주문 상품 스크롤 표시가 보인다.
- 결제 직전 가격과 판매 상태를 다시 확인한다.
- 관리자가 선택한 결제 모드와 문구가 정확히 표시된다.

### 완료·접수

- 주문 번호는 한 번만 생성된다.
- 계좌·QR 모드에서는 `결제 완료`가 아닌 `주문 접수`로 표시된다.
- 처음으로 버튼과 자동 초기화가 장바구니와 세션을 비운다.

### 관리자

- 비밀번호 없이는 진입할 수 없다.
- 상품명, 가격, 1:1 이미지, 카테고리, 노출과 품절 상태를 수정할 수 있다.
- 웰컴 배경과 결제 모드를 수정할 수 있다.
- 변경 사항이 고객 화면에 즉시 또는 새 화면 진입 시 반영된다.
- 백업 내보내기와 검증된 가져오기가 동작한다.

## 13. 1차 개발 범위에서 제외

- 실제 카드사·간편결제 PG 연동과 입금 자동 확인
- 온라인 쇼핑몰, 배송, 회원, 포인트와 쿠폰 시스템
- 외부 재고·ERP 연동
- 원격 관리자 계정과 다중 권한 관리
- 서버 기반 매출 분석 대시보드

실제 결제가 필요해지는 시점에는 결제 시뮬레이션을 실제 PG 흐름으로 교체하는 별도 설계와 보안 검토가 필요하다.

## 14. 구현 시 구조 원칙

- 화면 컴포넌트, 상품 데이터, 이미지 자산과 설정을 분리한다.
- 상품 카드와 주문 행은 데이터 배열을 기반으로 반복 렌더링한다.
- 상품 이미지 입력 단계에서 1:1 자르기와 파일 검증을 완료한다.
- 관리자 변경 내용을 고객 화면이 안전한 시점에 다시 읽도록 한다.
- 주문 생성은 중복 호출에도 결과가 하나가 되도록 처리한다.
- 샘플 데이터와 실제 운영 데이터를 분리해 교체가 쉽도록 한다.

이 문서는 승인된 기능 기준선이다. 이후 상품명, 가격, 이미지와 문구 변경은 관리자 데이터 변경으로 처리하며, 화면 구조나 결제 의미가 달라지는 변경만 본 명세를 개정한다.
